# WIP LOOP 전시용 관제

**기존 관제 디자인과 가상 충전·자동 복구 기능을 추린 독립 전시본입니다. 인터넷·CSMS·DB 없이 실행합니다.**

## 웹 배포

완성본 `web/`을 정적 웹사이트로 배포할 수 있습니다. 방문하는 PC에는 Python, Node.js, 배치 파일이 필요하지 않으며 Edge 또는 Chrome으로 배포 주소를 열면 됩니다. 인터넷 연결과 해당 사이트에 대한 접근 권한은 필요합니다.

- 일반 전시: https://wip-loop-amr-exhibition.ksm9604mm.chatgpt.site/#dashboard
- 대형 화면: https://wip-loop-amr-exhibition.ksm9604mm.chatgpt.site/?monitor=1#dashboard 에 접속한 뒤 F11
- 시뮬레이션은 각 브라우저에서 독립적으로 동작합니다. 새로고침하면 초기화되며 다른 PC와 상태가 공유되지 않습니다.

현재 웹사이트는 공개 상태이며 로그인 없이 접속할 수 있습니다. Sites 배포 설정은 `.openai/hosting.json`에 있습니다. 배포 전에 `node scripts/prepare-web-deploy.mjs`를 실행하면 완성본 `web/`을 게시 폴더 `dist/`에 복사합니다. GitHub에 코드를 올리는 것만으로 Sites가 자동 갱신되지는 않으며, 수정한 화면은 Sites에 별도로 배포해야 합니다.

다른 정적 호스팅을 사용할 때도 게시 폴더는 `web/`입니다. 현재 리소스 경로는 `/assets/`, `/fonts/`, `/brand/`처럼 사이트 루트를 기준으로 하므로 도메인의 루트 경로에 배포하세요. 소스 변경 후에는 `source/`에서 `npm ci`, `npm run build`를 실행한 뒤 갱신된 `web/`을 배포합니다.

## 로컬 실행

1. 이 `WIP_LOOP` 폴더 전체를 전시 PC의 로컬 디스크에 복사합니다.
2. Python 3.9 이상이 설치되어 있어야 합니다. 추가 Python 패키지나 Node.js는 실행에 필요하지 않습니다.
3. `전시_시작.bat`을 더블 클릭합니다. 브라우저가 자동으로 열립니다.
4. 대형 모니터에서는 `대형화면_시작.bat`을 사용하고, 브라우저에서 F11을 누르면 전체 화면이 됩니다.
5. 실행 창은 열어 둡니다. 종료할 때 창에서 Ctrl+C를 누릅니다.

기본 주소: http://127.0.0.1:5180/ . 포트 사용 중 오류가 나면 기존 실행 창을 종료하거나 `python serve.py --port 5182`로 실행합니다. `web/index.html`을 직접 더블 클릭하지 마세요.

## 포함 화면

| 화면 | 전시 내용 |
|---|---|
| 통합 관제 | 6대 가상 충전기, 구역, 도킹 AMR, 출력·온도·배터리, 장애 위치와 복구 진행 |
| 충전기 | 장비 검색·상세 계측·가상 충전 시작/중지 |
| 장애 · 자동 복구 | 원인 후보 → 보호 → 자동 조치 → 안정 확인 → 재충전 또는 현장 이관 |
| 충전 시연 | 도킹·정렬·인증·충전·이탈 애니메이션과 장애 시나리오 |
| 분석 리포트 | 전력량·세션·장애 집계, CSV 저장·인쇄 |
| 충전 이력 | 가상 세션 결과 |
| 운영 이력 | 발생 이벤트와 시연 중 조작 기록 |

관리자 설정·로그인·서버 자율 운영·개발용 원시 통신 로그·휴머노이드 내부 실증 자료는 제외했습니다. 실장비 제어, 외부 모델, DB 및 원본 사업 자료도 포함하지 않습니다.

## 권장 시연 순서

1. **통합 관제**에서 충전·대기·장애의 차이와 오른쪽 자동 복구 단계를 설명합니다. 처음의 6번 충전기는 도킹 로봇이 없으므로 냉각 후 대기로 돌아갑니다.
2. **장애 · 자동 복구**에서 충전 중인 `WPO-TX-04`를 선택합니다. `PD · 패드 재정렬`과 `가상 자동 재충전`을 선택하고 실행합니다.
3. 보호 정지 → PD 정렬 → 안전 확인 → 시험 충전 → 출력 상승 → 재충전 완료를 보여 줍니다. 통합 관제에서도 진행 상태를 볼 수 있습니다.
4. 충전이 재개된 뒤 `이물질 · 현장 이관`을 실행합니다. 이물질은 자동 재충전하지 않고 현장 조치를 요청하는 사례입니다.
5. **충전 시연**에서 충전 대기 중인 `WPO-TX-03`으로 정상 충전 동작을 보여 줍니다.
6. **분석 리포트**에서 시연 중 집계 결과를 확인합니다.

상단 **시연 초기화**는 확인 후 초기 상태로 돌아갑니다. 새로고침도 기록을 초기화합니다. 저장이 필요한 리포트는 먼저 CSV로 내려받으세요. 반복 시연은 초기화 후 시작합니다. 자동 반복 재생 기능은 포함하지 않습니다.

## 표시의 의미와 범위

- 모든 계측·장애·명령 응답은 브라우저에서 생성한 시뮬레이션입니다. 실제 현장 데이터나 OCPP 적합성 검증 결과가 아닙니다.
- 전시 시작 시 표시되는 누적 전력량과 이전 세션도 예제 데이터이며, 실행 중 가상 세션이 더해집니다.
- 원인 분석은 규칙 기반 원인 후보입니다. 실제 AI 모델·RAG·실장비 자동 복구에 연결된 화면이 아닙니다.
- 현재 수치와 장비 명칭은 기존 AMR 데모를 유지합니다. RB-Y1의 1.25 kW 성능이나 휴머노이드 실증 결과를 표현하지 않습니다.
- 시연 설정은 포함된 기본값을 사용하며, 원본 관제의 로그인·서버 설정·브라우저 저장값을 읽지 않습니다.
- 전시 서버는 127.0.0.1에서만 열리고 `web` 폴더만 제공합니다. 다른 PC에는 이 폴더를 복사하여 실행하세요.

## 폴더 구성

- `web/`: 바로 실행하는 완성본. 로고·한국어 폰트와 폰트 라이선스 포함.
- `serve.py`, `전시_시작.bat`, `대형화면_시작.bat`: 로컬 실행 도구.
- `source/`: 전시에 필요한 화면·시뮬레이터 소스와 빌드 설정.
- `shared/charging-settings.json`: 시연에 사용하는 기본 감지·보호 기준.

소스를 수정할 때만 Node.js가 필요합니다. `source`에서 `npm ci` 후 `npm run build`를 실행하면 `web`이 갱신됩니다. 새로 빌드한 뒤 브라우저를 새로고침하세요. 원본 `frontend`, `backend`, `docs`는 변경하지 않았습니다.

```powershell

cd wip_loop
.\전시_시작.bat
```
